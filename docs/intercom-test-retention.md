# Bounded intercom test retirement / migration

Scope: only `test/integration/{pi-intercom-runtime,intercom-hints}.test.ts`, `test/unit/pi-intercom-{inline-message,session-list,topics}.test.ts`, plus canonical `pi-intercom-native-replay.test.ts`. No production changes. Baseline tracked diff is `baseline.patch`; `baseline-untracked.tar` contains the original untracked files; exact original native/runtime files are preserved alongside them. Apply only the retirement DELTA after the prior local lane and final namespace lane.

## Evidence and decision rules

All five suites (6,768 lines) and the 2,407-line native keeper were read in full before edits. Current factory, connection, lifecycle/session events, inbound/journal/delivery, outbound/wait, inspection, argument/result owners, broker, paths, socket owner and target resolver were inspected. Relevant SDK runtime implementation/declarations were inspected on official 1.3 and intended immutable fork. The previous runtime fixture used genuine SDK registration but supplied its own lifecycle events, receipt publication, idle flags, and message sink. Those fixture-level assertions are not native runtime proof. New assertions use native provider, session, journal, socket or broker-process observations.

Relevant history: `d18d7b8d` (#195) explicitly pruned duplicates and repaired readiness; its safety contracts are preserved, not counted as obsolete merely because imports fail. `d4caa135` (#201) added later lifecycle/control integration; removed control/health/event bridges are not public contracts of the replacement factory. `3d12fd25` removed resource footer while retaining topic ownership; topics themselves are now explicitly retired. Inline completion/compact/mouse contracts belonged to the deleted message renderer and UI, not retained model delivery.

No remaining non-test caller of the deleted UI/supervisor/topic owner is introduced here. The replacement factory registers one eager plain tool and native lifecycle owners; no custom renderer, picker, topic registry, supervisor tool, health bridge, role/name environment bridge or context hint owner exists. Parent owns stale old-engine callers. Four obsolete suites are deleted. Runtime suite retains only six broker-process cases (one parameterized declaration expands to two); native contracts migrate to the canonical native replay keeper. No test-only production exports, injection flags or dependency changes.

Legend: **R** retired product contract, no replacement needed; **M** distinct retained contract migrated; **K** stronger existing native keeper already owns it; **B** retained at real broker process boundary. Keeper labels below refer to full test names in current files. Exact original locations and declaration expressions are also preserved in `test-inventory.json`; parameter values are expanded below.

## Primary keepers

- **targets**: `native public tools resolve displayed targets safely through duplicate names and prefix collisions` (unit target resolver remains separately owned).
- **reconnect**: `native reconnect retries after a failed background launch`; `native reconnect retries after a failed foreground takeover during backoff`. Both require a subsequent real launcher process after the failed attempt, then automatic native re-registration and passive delivery after broker recovery; merely observing the first launcher start is insufficient.
- **busy asks**: `native ordinary asks honor busy capability and explicit steer/queue without claiming consumption`.
- **ask outcomes**: `native ordinary ask {timeout,disconnect,cancel,failure-marker,normal-prefix} settles with its original correlation and releases the waiter`.
- **provider errors**: `native recipient provider failure {on its first turn,after a tool turn} reaches the ordinary ask as an error`.
- **no spurious errors**: `native {already-replied,agent-settled,non-error} does not produce a spurious recipient-failure reply` (same-recipient ordered control send is the negative-check barrier).
- **replacement asks**: `native replace asks retire superseded pending questions and wake once after {UI tool,print provider} work settles`.
- **validation**: `native public tool rejects invalid delivery combinations and preserves recovery actions`.
- **shutdown**: `native {reload,dispose} joins admitted socket registration before invalidation and preserves other broker clients`; `native runtime disposal cancels deferred startup before any broker registration`; `native runtime disposal cancels queued inbound work without a later wake`. Dispose case invokes actual `AgentSessionRuntime.dispose`, checks socket closure at `setBeforeSessionInvalidate` while old context still works, then actual stale context. It is not claimed from reload.
- **presence**: `native lifecycle presence follows parallel tools, selected model and final settlement` also observes actual agent_end still thinking/not accepting asks before final settlement.
- **print policy**: `native busy print work auto-replies to ordinary asks without aborting and admits only the latest replacement at its tool boundary`.
- **existing delivery**: native idle/passive, busy steer/queue/passive, 101-message abort/reload recovery, selected default ask, exact ordinary reload correlation, immediate ordinary progress, latest backdated milestone, cold SIGKILL/resume/fork/new-session keepers. Their original names and assertions remain in native suite.
- **broker**: six remaining tests in `pi-intercom-runtime.test.ts` preserve idle exit, expanded-forward-frame rejection plus healthy subsequent send, invalid presence isolation, 101 unique replacement threads, staged send survival and staged ask retirement after sender disconnect. Sender-disconnect cases also exercise same-thread idle coalescence and use a later processed replacement window, not a fixed sleep, before absence assertions.
- Namespace tests own lineage, pid/path isolation, framing/parsing and last-message relay safety. They are not duplicated here.

## Async-only redesign (detach probe retired)

The busy-recipient detach request/response probe and its 500 ms timer were removed with
blocking child waits. `native ordinary/ask steer bursts bound unanswered handshakes` was
deleted: it only counted listeners of the retired probe. Burst ordering, exactly-once
visibility and reload draining remain covered by the native recovery, restored-backlog and
hard-kill resume keepers. The recovery-arrival test keeps its staged `flushDelivery` steer
assertion without the probe listener. The correlated busy-steer test now releases its held
tool only after observing the native stage while the provider call count is still 1, then
asserts the question and reply after the tool boundary.

## Risks and verification

Official1.3 direct runtime.dispose while a provider is active does not await final settlement: that invalid fixture produced native stale-context events. The queued-work disposal test instead disposes an idle runtime after its actual queued question checkpoint is observed, then observes a later real broker/native replacement window on another runtime before checking no disposed wake. It does not claim active-run cancellation/settlement or child-process stop ownership; those remain parent/core contracts.

Principal risk is deleting distinct safety assertions hidden among obsolete UI tests. Mitigation: explicit keeper mapping above, genuine socket/process barriers, actual SDK runtime disposal, official/fork separate checks. No source behavior is changed to satisfy a test. Historical red was not reconstructed; no test-first claim. Required proof is focused official1.3 and intended-fork native/runtime tests, focused strict lint, full format/diff checks and full lint/typecheck diagnostics with integration residue disclosed. Exact final results are recorded in `RESULTS.md` after verification.
